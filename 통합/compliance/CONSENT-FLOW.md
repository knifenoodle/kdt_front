# 보호자 동의 플로우 (G2-1)

근거: `knowledge_base/legal/LEGAL-003_개인정보보호법_아동특례.md` (status active, severity **critical**)

**1단계 상태: 미구현. 그러나 위반도 아니다** — 저장·전송하는 개인정보가 0건이기 때문이다(D2, STT 제외).
🚨 STT 텍스트를 1건이라도 저장하는 순간 이 문서 전체가 필수가 된다.

## LEGAL-003 이 요구하는 것

| 규칙 | 요구사항 | 현재 |
|---|---|---|
| R1 | STT 원본·대화 로그·프로필은 **법정대리인 동의 후에만** 수집·저장 | 해당 기능 부재 |
| R2 | RAG 개인화용 아동 프로필 **최소 수집**, 목적 외 사용 금지 | 프로필 기능 부재 |
| R3 | 부모 리포트는 **법정대리인에게만**, 접근 시 대리인 인증 | 리포트 부재 |
| R4 | 음성 데이터 **보관 기간 명시** + 열람·정정·삭제 절차 | `RETENTION-DELETION.md` |
| R5 | 아동에게 직접 받을 수 있는 정보는 **동의 확인용 최소 정보로 제한** | ✅ `age_band` 만 |

`:37` 자기 고백: "법정대리인 동의 확인 방식(문자 인증 등 대통령령이 정하는 방법)의 구체적 구현은 **법무 검토 후 확정 필요**."
→ 이 문서도 그 미확정을 승계한다. 단계를 나눠 기록한다.

## 설계

**동의 시점**: 첫 실행 시, **아이 화면 진입 전**. 아이가 앱을 열었을 때 이미 동의가 끝나 있어야 한다.

**동의 항목 분리** (일괄 동의 금지)

| 구분 | 항목 | 1단계 |
|---|---|---|
| 필수 | 음성의 **일시적 처리**(STT 변환 후 즉시 파기) | 해당 없음 (STT 제외) |
| 선택 | STT 텍스트 보관 (리포트용, 기본 **꺼짐**) | 해당 없음 |
| 선택 | 연습 기록 집계 (보호자 리포트) | D5 조건부 |

**아이에게서 받는 정보**: `age_band` (`'4'|'5'|'6'`) **하나뿐**.
`uiux기획/CLAUDE.md:107` — "아이 온보딩에서 이름·생년월일을 받지 않는다."
현재 `SessionRequest` 가 `extra='forbid'` 로 이를 강제한다(실측 4/4 거부).

**동의 확인 방법** — 단계별

| 단계 | 방법 | 근거 |
|---|---|---|
| Phase 1 (현재) | 해당 없음 — 처리하는 개인정보 0건 | |
| Phase 2 | 보호자 자기확인 + **연락처 미수집**. 두 자리 덧셈 게이트로 성인 확인 | `LEGAL-003:37` 미확정 상태 승계 |
| Phase 3 | 문자 인증 등 대통령령이 정하는 방법 | **법무 검토 후 확정** |

🚨 Phase 2 를 "동의 확인 완료"로 표현하지 않는다. 덧셈 게이트는 성인 확인 장치이지 법정대리인 확인이 아니다.

**철회 경로**: 보호자 화면 > 데이터 삭제. 게이트 뒤에 둔다(`uiux기획/CLAUDE.md:101`).

## ParentGate 와의 관계

`uiux기획/CLAUDE.md:99-102`
- **롱프레스를 게이트로 쓰지 않는다** — 만 4~6세가 가장 잘하는 동작이다
- 게이트는 **두 자리 덧셈 4지선다**, 매번 난수 생성
- 게이트 뒤: 결제·구독·리포트 전문·사용 시간·계정·데이터 삭제
- 게이트 화면 자체를 **아이가 보기 지루하게** — 애니메이션·사운드 없음

**현재 미구현**: `mockup-v1.html:2295` 가 `toast('보호자 화면은 덧셈 게이트 뒤에 있어요 (다음 단계에서 구현)')` 스텁이다.
게이트 뒤에 둘 것이 아직 없어 무해하나, 리포트·삭제·결제 중 **하나라도 구현되는 순간 G1 로 승격**된다.
