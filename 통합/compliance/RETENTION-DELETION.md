# 보관·삭제 정책 (G2-4)

근거: `LEGAL-003-R3`, `LEGAL-003-R4`, `GOV-002-R4`

## 오해 정정 — 충돌이 아니다

`uiux기획/CLAUDE.md:110`("음성 녹음은 STT 처리 후 **즉시 파기**")과
`LEGAL-003-R4`("보관 기간을 **명시**하고 열람·정정·삭제 절차 마련")는 **충돌하지 않는다.**

R4 는 *"보관한다면* 기간을 명시하라"는 **조건부 규칙**이고,
즉시 파기는 **"보관기간 = 0초"로 명시함으로써 R4 를 만족**한다.

진짜 충돌은 다른 곳이다 — **즉시 파기 ↔ 부모 리포트의 증거 기반**(`README.md §2-③`).
D5 로 지수 리포트를 유지하기로 했으므로 항목별로 분리해 해소한다.

## 보관 기간

| 항목 | 보관 기간 | 근거 | 1단계 |
|---|---|---|---|
| **오디오 원본** | **0초 — 저장하지 않는다** | `uiux기획/CLAUDE.md:110`. 어느 분기에서도 예외 없음 | 해당 없음(마이크 비활성) |
| STT 텍스트 | 기본 **미보관**. 보호자 옵트인 시 N일 | `LEGAL-003-R1` (동의 선행) | 해당 없음 |
| 위험 발화 감지 기록 | **유형·시각만** (원문 미보관) | `RISK-ESCALATION-POLICY.md` 미해결 ①. 이것도 저장이므로 동의 선행 | 해당 없음 |
| 연습 기록 집계값 | 보호자 계정 유지 기간 | D5 | 해당 없음 |
| 서버 로그 | 요청 메타만. **본문 미기록** | 상관 ID로 추적 | ✅ 적용 중 |

🚨 **N일의 구체값은 정해지지 않았다.** 보호자 리포트 설계 시 확정하고 이 표에 기입한다.
"적절한 기간" 같은 표현으로 남기지 않는다 — R4 는 **명시**를 요구한다.

## 삭제 절차

| 항목 | 내용 |
|---|---|
| 요청 경로 | 보호자 화면 > 데이터 삭제 (**게이트 뒤**) |
| 인증 | 법정대리인 인증 (`LEGAL-003-R3`, `GOV-002-R4`) |
| 응답 기한 | 요청 후 **10일 이내** (개인정보보호법 시행령 기준) |
| 범위 | STT 텍스트 · 집계값 · 위험 발화 기록 전부 |
| 확인 | 삭제 완료를 보호자에게 통지 |

## 🚨 "즉시 파기"는 주장이 아니라 **테스트로 증명**한다

문장만으로는 부족하다. 처리방침의 근거가 되려면 기계적으로 확인 가능해야 한다.

**불변식 S6** (`check-safety-rules.mjs`) — 현재 통과 중
- 전 코드베이스에 `localStorage`/`sessionStorage`/`indexedDB`/`AsyncStorage`/`SecureStore` **0건**
- 화이트리스트 예외 1곳: `src/lib/consent.ts` (보호자 동의 플래그, 미작성)

**추가 필요 (STT 활성화 시)**
- 런타임 단정: 녹음 파일 핸들이 STT 전송 완료 후 `deleteAsync()` 로 삭제됨
- 서버측: STT 응답 처리 후 원본 바이트가 메모리에서 해제되고 디스크에 쓰이지 않음

## 현재 상태 요약

**1단계는 완전 무상태다.** DB·세션·쿠키·파일쓰기·클라이언트 저장소가 전부 0건이며
(`DATA-FLOW-INVENTORY.md` 검증), 따라서 삭제할 데이터 자체가 존재하지 않는다.

이것은 "잘 설계해서"가 아니라 **"기능이 아직 없어서"** 달성된 상태다.
STT/프로필/리포트가 착륙하면 이 문서 전체가 즉시 필수가 된다.
