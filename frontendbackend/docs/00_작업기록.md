## 0. 출발점

`frontendbackend/` 는 `CLAUDE.md` 한 파일뿐인 빈 폴더였다. 두 소스를 분석했다.

| | 백엔드 | UI/UX |
|---|---|---|
| 경로 | `백엔드/Communication_simulator` | `프론트` |
| 정체 | FastAPI + Gemini **텍스트 배치 생성기** | 또랑 — **만 4~6세 음성 전용** 앱 |
| 규모 | 1,589행 / 4커밋 / 원격 있음 | `mockup-v1.html` 2,369행 + 에셋 22개 |
| 상태 | 무상태(DB·세션·인증·로깅 0) | 외부 요청 0건, 완결 동작 프로토타입 |

### 첫 번째 판단: 이건 같은 제품의 앞뒤가 아니다

백엔드는 **6개 산문 필드 + 첫 대사 1줄**을 emit한다. UI는 **3턴 대화 트리**(턴당 `ask/hint/sup1/sup2/back` + 감정 2종 = 15줄 + 6태그)를 요구한다.

필드명 불일치가 아니라 **생성 능력의 부재**였다. 이것을 "리네이밍으로 해결되는 문제"로 오해했다면 1단계 전체가 헛돌았을 것이다.

## 1. 되돌린 것 / 틀린 것

### 되돌린 것 ①: "백엔드 절대 기준"을 문면대로 적용하려던 것

`CLAUDE.md:14`는 충돌 시 백엔드를 절대 기준으로 삼으라고 한다. 그런데 아동 안전 축에서는 **백엔드가 열등한 쪽**이었다.

- UI: `mockup-v1.html:1609-1613` — "송편은 상황에 반응한다. **아이의 발화에는 반응하지 않는다.** … 아이는 예외 없이 그것을 '내 대답에 대한 채점'으로 읽는다"
- 백엔드: `README.md:54` — "실시간 채점"

문면대로 적용하면 **모든 안전 충돌이 약한 쪽 승리**로 판정된다. → D6으로 안전 예외 조항을 신설했다.

### 되돌린 것 ②: 연령 충돌을 "3파 대립"으로 본 것

세 산출물이 7~9세 / 4~6세 / 6~8세로 갈라져 보였다. 실제로는 **최신 기획서가 이미 확정**해 둔 상태였다 — `아이디어_개발_기획서_양식반영본_v4.md:119` "1순위 대상은 미취학 만 4~6세, 설계 기준 페르소나는 만 5세… 초1~3 확장의 경로".

게다가 백엔드의 `age_range`는 enum 없는 `Optional[str]` 런타임 인자라 **백엔드가 이미 호출자에게 결정을 위임**하고 있었다. 애초에 우선순위 규칙의 판정 대상이 아니었다.

→ 사용자에게 물을 필요가 없는 질문이었다. 물었다면 시간만 썼다.

### 되돌린 것 ③: 연출 3건이 미결이라고 본 것

`캐릭터연출_기획_v1.md:145/165/185`에 "사용자 결정 필요 ①②③"이 있었다. 그런데 같은 파일 `:638`이 **"부록 — 사용자 결정 3건 · ✅ 2026-08-04 전부 결정"**이었다. 인라인 마커가 stale이었을 뿐이다.

→ 원본을 수정하지 않으므로 `docs/02` §C와 `DECISIONS.md` D7이 오독 방지 장치 역할을 한다.

### 되돌린 것 ④: 원본을 직접 수정하던 방식 (2026-08-05)

가장 큰 되돌림이다. 당초에는 원본을 직접 고치되 사본·기록을 남기는 예외 절차(D4)로 4건을 수정했다.
사용자 결정으로 **"복사해서 작업하고 원본은 원본대로 유지"** 로 전환했고, 원본 4건을
`git checkout -- .` 으로 전부 되돌린 뒤 `engine/` 사본에서 다시 적용했다.

**이 전환이 예상 밖으로 큰 이득을 줬다.**

`docs/04` 에서 CS-002(fail-open)와 CS-006(중첩 스캔 실명)을 **"보류 — 상류 PR 권한 확인 필요"**
로 남겨뒀었다. 둘 다 HIGH 이고 G1 인데 유일한 차단 사유가 **소유권**이었다.
복사본이 우리 것이 되면서 그 차단이 사라졌고, 둘 다 바로 고쳤다.

| 결함 | 수정 전 실측 | 수정 후 |
|---|---|---|
| CS-002 | 잘못된 category + HTML 페이로드 → `is_valid=True` | severity 단일화 + 카테고리 위반 critical 승격 → 차단 |
| CS-006 | `{'x': {'y': '칼로 협박했다'}}` → `is_valid=True` | dict/list/tuple/set/str 재귀 순회 → 차단 |

동시에 **우회 장치 3개가 필요 없어졌다**. 벤더링 seam(모듈 속성 오버라이드), top_k in-process
래핑, 원본 트리 경로 탐색(한글·공백 취약)이 전부 직접 수정으로 대체됐다. `deps.py` 가 절반으로 줄었다.

**교훈**: "권한이 없어서 못 고친다"를 부채로 기록해 뒀던 게 옳았다. 소유권이 바뀌자마자
무엇을 고쳐야 하는지가 이미 문서화되어 있어 바로 실행할 수 있었다.

**부수 확인**: GDL-001 재작성(문장 10단어)이 실제로 생성 결과를 바꿨다.
재작성 전 `"야, 이 빨간 자동차 진짜 멋지다! 내가 지금 가지고 놀래!"` →
재작성 후 `"나 이 자동차 지금 놀래. 나 줘!"`


### 틀린 것 ①: LEGAL-003 오염의 심각도를 과대평가했다

"난타 문자열과 raw YAML이 Gemini 시스템 프롬프트에 주입된다"고 HIGH로 보고했다.

**실제로는 프롬프트 주입이 일어나지 않는다.** `rule_engine.py:71-75` `_extract_rule_lines`가 `- **[` + `-R` 패턴 라인만 통과시켜 YAML·난타를 걸러낸다. 실제 피해는 ① 심사 노출 ② 키워드 점수 오염 ③ 벡터 RAG 승격 시 임베딩 오염이다.

→ HIGH → MED로 하향. 그래도 고쳤다(1행 수정으로 세 문제가 동시 해소되는 최고 가성비 항목이었다).

### 틀린 것 ②: `physical_boundary` 빈 배열 가설이 재현되지 않았다

라벨이 "장난으로 치고 가기"이고 금지어에 `"때려"`가 있으니 빈 배열 확률이 가장 높으리라 예측했다.

실측(실제 키): `physical_boundary` 3회 + `verbal_discomfort` 4회, **총 7회에서 검증 거부 0건.**

→ 제 보고 규칙("재현 불가 시 심각도 하향 + `[가설]` 표기")을 제 발견에 그대로 적용해 강등했다. 빈 배열 경로는 실측 대신 단위 테스트로 커버한다.

⚠️ 거부 0건이 CS-003 수정(ETH-002·GDL-001 승격)과 정합하지만 **대조군을 측정하지 않았으므로 인과로 주장하지 않는다.**

### 틀린 것 ③: "CSS Modules가 번들에서 빠졌다"

CSS 파일 두 개 중 첫 번째(439 bytes = globals만)를 보고 버그라고 판단했다. 실제로는 둘 다 링크되어 있었고 두 번째(7,289 bytes)에 76/88/56px과 감정 CSS가 전부 들어 있었다.

### 틀린 것 ④: 검사기가 자기 주석을 위반으로 잡았다

`check-safety-rules.mjs` S10이 `speak.ts`의 **후행 주석**에 있는 연령 문자열을 위반으로 잡았다. 규칙을 *설명하는* 주석까지 잡으면 검사가 못 쓰게 된다.

→ 공통 `strip()` 헬퍼로 블록·행·후행 주석을 제거하되 `http://`의 `//`는 건드리지 않게 고쳤다.

### 틀린 것 ⑤: 계획서에 쓴 CS-010 완화책이 실행 불가였다

"BFF가 `top_k`를 명시 전달한다"고 계획했다. 그런데 `build_rule_sections`(`rule_engine.py:34`)가 `top_k`를 **전달하지 않는다** — 호출자가 인자로 넘길 방법이 자체가 없었다.

→ 처음엔 in-process 래핑으로 우회했다. 이후 engine/ 사본 전환으로 `rule_engine.py` 를 **직접 수정**했고 래핑은 제거했다(되돌린 것 ④).

### 어댑터를 서버에 둔 이유

프런트에 두면 (b)로 갈 때 프런트를 다시 뜯어야 하고, "아이가 들을 문장을 조립하는 로직"이 브라우저에 노출된다. BFF에 두면 어댑터 파일 하나 교체로 끝난다.

### 웹을 택한 결정적 근거 (실물로 확인됨)

`프론트/CLAUDE.md:19`가 웹 전환을 사전 승인해 뒀지만, 결정적인 건 **에셋 구조**였다.

`songpyeon-green.svg`를 열어 보니 감정 표현이 **SVG 내부 `<style>`의 `display` 토글**로 되어 있었다(`.m-smile`/`.m-frown`/`.blush`/`.tear`…). `<img>`로 넣으면 외부 CSS가 내부에 닿지 못해 **표정이 전혀 바뀌지 않는다.** RN에서는 감정 8종 × 캐릭터 11종을 `react-native-svg`로 전부 재작성해야 한다.

→ 이건 취향 문제가 아니라 자산이 이미 결정해 둔 문제였다.

### 1단계 합격선을 "API 키가 죽어도 돈다"로 잡은 이유

해커톤 시연에서 가장 흔한 실패는 정상 경로가 아니라 부정 경로다. 키 만료·쿼터 소진·네트워크 문제로 데모가 멈추면 아무것도 보여줄 수 없다.

→ `/api/session`은 **상류 실패로 실패하지 않는다.** 키 부재·빈 배열·타임아웃·상류 예외 4종 전부 저작 폴백으로 200을 반환하고, 사유는 `source.fallback_reason`에만 남는다. 아이 화면은 차이를 인지하지 못한다.

이건 편의 기능이 아니라 **안전 요구사항이기도 하다** — `프론트/CLAUDE.md:81` "아이 화면에 오류 색 자체가 없다".

## 7. 기획 대비 미구현 감사 + STT 무관 결함 일괄 수정 (2026-08-05)

§6 배포 직후 라이브 브라우저(puppeteer-core, Chrome 실제 `cancel()` 시맨틱 재현)로 실측
감사를 진행해, 레벨시스템 v1.2 §3-2가 "즉시 반영 필수"로 지정한 VUI 3종 중 화면에서 실제
작동하는 것이 0개임을 확인했다. STT 부재(D2)로 원천 불가능한 것과 STT와 무관하게 그냥
안 되어 있던 것을 구분한 뒤, 후자를 전부 수정했다. 상세 근거는 `docs/10_UIUX_리뷰.md` H1~H10.

| 결함 | 원인 | 수정 |
|---|---|---|
| H1 지원(힌트) 3단계 미재생 | `retry()`/`supportSlot()` 호출처 0건(死코드) | `Talk.tsx`에 무응답 타임아웃(7s) 기반 hint→sup1→sup2 승급 배선. STT 없이 "미통과"를 판정할 수 없으므로 시간 초과를 트리거로 사용 |
| H2 "다시 듣기" = 건너뛰기 | `speak()`의 `shutUp()`이 이전 발화 `onend`를 즉시 발화 → 다음 대사로 오인 진행 | `speak.ts`에 세대 토큰(`activeId`) 도입, 교체당한 발화의 onEnd는 무시 |
| H4 보상 음성·그림 불일치 | 매 세션 `lines.party`("다 모았어!") 재생, 실제론 1~5/6층 | 완주 세션에만 `party`, 그 전엔 `LINES.layerFilled`(활동기록형, 무비교) |
| H5 배경 씬 10종 전부 안 보임 | `.talk`가 `position:relative`인데 `z-index` 없어 새 스태킹 컨텍스트 미형성 → Scene의 `z-index:-1`이 페이지 루트 기준으로 적용돼 `.talk` 자체 배경보다 뒤로 밀림 | `.start/.talk`에 `z-index:0` 추가 |
| H6 TTS 워치독 없음 | `onend`/`onerror` 무응답 시 세션 영구 정지 | `speak()`에 글자수 비례 워치독 타이머 추가 |
| H7 가로 모드 주 버튼 화면 밖 | 크기 기반 미디어쿼리 0개 | `@media (max-height:500px)`에서 `transform:scale(0.5)` 균일축소(mockup `fit()` 취지 재현) |
| H9 영어 오류/404 페이지 노출 가능 | `app/error.tsx`·`app/not-found.tsx` 부재 | 캐릭터 `canthear` + 한국어 문구로 신설 |
| H10 `/__dev` 무인증 프로덕션 노출 | 빌드 플래그 없음 | `NODE_ENV==='production'`에서 `notFound()`, 프로덕션 번들 크기 0B로 확인 |
| 고도화안 §1-1 콜 앤 리스폰스 미전환 | sup2 21줄 전부 "같이 말해보자"(동시발화) 원문 유지 | 9개 데크 sup2 전체를 "내가 먼저 말할게…이어서 ~해봐" 형태로 재저작 |
| §2-3 아동별 2/3 변이 조합 없음 | `levelPlan.ts`가 v1·v2 고정 하드코딩, 변이3은 영구 배제 | 라운드(6층 완주)마다 레벨당 변이 2개를 무작위로 재추첨(`rerollPlan()`). 부수 효과로 변이3 3종도 라운드에 걸쳐 자연 등장 — §1-1 "복습 모드"가 요구한 것(남는 변이의 후속 재활용)을 별도 상태 없이 충족 |

**의도적으로 보류한 것** — legal/설계 결정이 선행돼야 하는 항목이라 이번 배치에 포함하지
않았다. 사유는 각 문서가 이미 규정.
- **진행도 영속저장**: 클라이언트 저장소 사용 0건이 안전 불변식(S6)으로 강제돼 있고,
  통합안 §5-2가 "보호자 동의 플로우 완료가 저장의 전제조건"이라 명시. 동의 플로우 없이
  `localStorage`를 추가하면 그 자체가 PIPA 리스크가 된다.
- **보호자 게이트·동의 화면**: 위와 동일한 이유로 법무 검토 선행 항목(§5-2).
- **H8 화자 미표시**: 버그가 아니라 미완성 설계 항목(말풍선에 화자 이름 없음) — 이번
  버그 수정 배치와 성격이 달라 별도 논의로 남긴다.

검증: pytest 66건, `tsc --noEmit`, `check-safety-rules.mjs` 15건, `next build`(프로덕션에서
`/__dev` 0B 확인) 전부 통과. 라이브 Chrome 재현(Chrome의 `speechSynthesis.cancel()` → 즉시
`onend` 발화 시맨틱 포함)으로 지원 사다리 전체 재생·다시 듣기 반복·보상 문구 일치·무작위
변이 배정을 실측 확인.
