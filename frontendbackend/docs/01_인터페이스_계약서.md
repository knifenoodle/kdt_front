# 인터페이스 계약서 — 또랑(web) × BFF × Communication_simulator

**이 문서가 연동의 정본이다.** 모든 필드에 `출처` 라벨이 붙어 있고, 라벨은 세 값만 가진다.

| 라벨 | 의미 | 변경 권한 |
|---|---|---|
| **[백엔드 실측]** | `contracts/backend-observed/`의 실제 응답에서 확인된 것 | **없음.** 백엔드 절대 기준. 리네이밍·형변환 금지 |
| **[신설]** | 백엔드에 개념 자체가 없어 새로 만든 것 | 있음. 단 "백엔드가 나중에 이 필드를 갖게 되면 어댑터만 삭제" 형태를 유지해야 함 |
| **[UI 요구]** | `uiux기획` 문서 위계가 규정한 것 | 없음. 아동 안전 축에서는 `uiux기획`이 백엔드보다 우선(`frontendbackend/CLAUDE.md` §3-2 안전 예외) |

- 실측 근거: `contracts/backend-observed/` (2026-08-04 채취, 5/8종 확보 · LLM 3종 보류 — 키 부재)
- 기계 계약: `contracts/session-script.schema.json` (JSON Schema Draft 2020-12, 유효성 검증 통과)
- 충돌 판정 근거: `docs/02_충돌해결_매트릭스.md`

## 0. 계층 구조

```
web (Next.js 15)  ──HTTP──▶  BFF (frontendbackend/server, :8100)
                                 │
                                 ├─ SessionScriptAdapter          ← 교체 가능 지점
                                 │
                                 └─in-process import──▶  rule_engine  (원본, 읽기 전용)
                                                              │
                                                              └──▶ Google Gemini
```

**web은 백엔드를 직접 호출하지 않는다.** 이유 3가지:
1. 원본에 CORS 미들웨어가 전무하다(`webapp/main.py` 전체에 `add_middleware` 0건) → 별 오리진 SPA는 브라우저가 차단
2. 오류 형태가 두 가지로 갈린다(§2.4) → 정규화 지점이 필요
3. `category`/`age_range`가 무검증으로 `system_instruction`에 도달한다(CS-005) → 화이트리스트 경계가 필요

BFF는 원본을 HTTP 프록시하지 않고 **`rule_engine`을 in-process import**한다(`webapp/main.py:14`와 동일한 `sys.path` 방식). 프로세스가 1개이므로 배포·시연이 단순하고, `PROMPT_CONFIG_PATH` 오버라이드 seam을 쓸 수 있다.

## 1. 원본 백엔드 계약 (읽기 전용 · 절대 기준)

### 1.1 `GET /api/categories`

**[백엔드 실측]** `contracts/backend-observed/categories.200.json`

요청: 없음. 응답 200:
```json
{
  "ownership_turn": "소유권/순서 마찰 (예: 장난감 뺏기, 새치기)",
  "physical_boundary": "신체적 경계 침범 (예: 원치 않는 포옹, 장난으로 치고 가기)",
  "verbal_discomfort": "언어적 불편함 (예: 싫어하는 별명 부르기)",
  "rule_violation": "놀이 규칙 위반 (예: 술래잡기에서 규칙 안 지키기)"
}
```

⚠️ **래퍼 키가 없다.** `{"categories": {...}}`가 아니라 bare object다. `webapp/main.py:51-54`가 `config["scenario_categories"]`를 그대로 반환한다.
타입: `Record<CategoryId, string>` where `CategoryId = 'ownership_turn' | 'physical_boundary' | 'verbal_discomfort' | 'rule_violation'`.
파일을 매 요청마다 새로 읽는다(캐싱 없음).

### 1.2 `GET /api/rules?category=<str>`

**[백엔드 실측]** `rules.ownership_turn.200.json`, `rules.bogus.200.json`

```json
{ "category": "ownership_turn", "rule_sections": "## ⚖️ 법적 규제 …\n- **[LEGAL-001]** …\n  - **[LEGAL-001-R1]** …\n\n## 🏛️ …" }
```

- `rule_sections`는 **단일 마크다운 문자열**이다. 구조화 데이터가 아니다. 규칙별 칩·출처 인용 UI를 원하면 서버 재구조화가 필요하다(`Rule` dataclass에 `id/title/source_name/source_url/severity/category`가 이미 있으므로 Phase 2 상류 PR 후보).
- 섹션 순서 고정: `legal → government → ethics → guideline` (`rule_engine/config.py` `CATEGORY_ORDER`).
- 🚨 **`category`가 무검증이다.** `rules.bogus.200.json`이 증거 — `?category=bogus`도 **200 + 그럴듯한 규칙 텍스트**를 반환한다. 파라미터 누락만 422.
- CS-003 승격 반영 후 활성 규칙 9건, `ownership_turn` 섹션 길이 4,865자.

### 1.3 `POST /api/generate`

**[백엔드 실측]** 요청 모델 — `webapp/main.py:40-43` 원문:
```python
class GenerateRequest(BaseModel):
    category: str                                        # 무검증 (enum 아님)
    num_scenarios: int = Field(default=2, ge=1, le=5)
    age_range: Optional[str] = None                      # 무검증 자유 문자열
```

응답 200:
```json
{
  "scenarios": [
    { "category": "ownership_turn", "scenario_title": "…", "background": "…",
      "conflict_trigger": "…", "learning_goal": "…", "ai_first_message": "…" }
  ],
  "issues": [ { "rule_id": "LEGAL-001", "field": "content", "message": "금지 키워드 '때려' 감지됨.", "severity": "critical" } ]
}
```

`scenarios[]` 6필드는 전부 필수 문자열이고 기본값·alias가 없다(`scenario_generator.py:59-65` Pydantic `Scenario`, Gemini `response_schema`로 강제).

**프런트가 반드시 다뤄야 하는 3가지 정상 동작:**
1. `scenarios`가 **`[]`인데 HTTP 200** — 모든 후보가 검증 탈락한 경우(`scenario_generator.py:143`). 오류가 아니다.
2. `scenarios.length < num_scenarios` 가능 — 패딩하지 않는다.
3. `issues[]`가 **재시도 시도 간 중복 누적**되고 **시나리오 인덱스가 없다**(`main.py:77-82`). 어느 시나리오가 왜 거부됐는지 매핑 불가.

### 1.4 오류 형태 — 두 가지가 호환되지 않는다 (M3의 근거)

**[백엔드 실측]** `generate.422.json` / `generate.500-nokey.json`

| 상태 | 트리거 | `detail` 타입 | 실측 본문 |
|---|---|---|---|
| 422 | Pydantic 위반 (`num_scenarios` 범위 밖, `category` 누락) | **배열** | `[{"type":"less_than_equal","loc":["body","num_scenarios"],"msg":"Input should be less than or equal to 5","input":9,"ctx":{"le":5}}]` |
| 500 | `GEMINI_API_KEY` 미설정 (`main.py:71-73`) | **문자열** | `"GEMINI_API_KEY 환경변수가 설정되어 있지 않습니다. …"` |
| 502 | 그 외 전체 예외 (`main.py:74-75`) | **문자열** | `"AI 호출 중 오류가 발생했습니다: {exc}"` — SDK 예외 원문 누출 (보류 채취) |

`webapp/static/index.html:304`가 `data.detail || '...'`로 처리하므로 422에서 `[object Object]`가 렌더된다. **BFF가 두 형태를 모두 흡수한다.**

## 2. BFF 계약 (신설 · web이 소비하는 유일한 API)

Base: `http://127.0.0.1:8100`. 프로덕션/시연에서는 web 정적 산출물도 같은 오리진에서 서브한다 → **CORS 문제 소멸**.

### 2.1 `GET /api/health`

**[신설]**
```json
{ "ok": true, "gemini_key_present": false, "rules_loaded": 9,
  "active_rules": ["LEGAL-001","LEGAL-002","LEGAL-003","GOV-002","GOV-003","ETH-001","ETH-002","GDL-001","GDL-002"],
  "retriever_pool": 8, "top_k": 8, "adapter": "template_deck",
  "prompt_config": "ttorang", "source_tree_found": true }
```

- 🚨 **키의 값·앞자리·길이를 절대 반환하지 않는다.** 존재 여부 boolean만.
- `retriever_pool` / `top_k`는 CS-010 감시용. `retriever_pool > top_k`면 규칙이 조용히 탈락 중이라는 뜻이다.
- `source_tree_found`는 `sys.path` 래핑 실패를 명확히 말하기 위한 것(소스 경로에 한글·공백이 있어 인용 실수가 반복될 지점).

### 2.2 `GET /api/categories`

**[백엔드 실측 그대로 통과]** 형태를 바꾸지 않는다. 래퍼를 추가하지 않는다.
`/__dev` 하네스만 사용한다 — 제품 경로에서 아이는 주제를 고르지 않는다(`uiux기획/CLAUDE.md:47` 글자 없이 작동, `:54` 한 화면 한 행동). 카테고리 선택은 보호자 게이트 뒤로 간다.

### 2.3 `POST /api/session` — 유일한 세션 진입점

요청:
```json
{ "category": "ownership_turn", "age_band": "5", "scene": "kids" }
```

| 필드 | 출처 | 검증 |
|---|---|---|
| `category` | **[백엔드 실측]** | 4값 `Literal` **강제**. 위반 → 400 (원본은 200을 주지만 BFF가 막는다) |
| `age_band` | **[UI 요구]** | `'4'\|'5'\|'6'`. BFF가 서버 정의 라벨로 번역해 백엔드 `age_range`에 전달 |
| `scene` | **[UI 요구]** | 10값 enum. 생략 시 어댑터 기본값 |

🚨 **`name`/`birthdate`/`child_id`/`school`/`grade`/`gender` 필드는 스키마에 존재하지 않는다.** `uiux기획/CLAUDE.md:107`("아이 온보딩에서 이름·생년월일을 받지 않는다. 필요한 건 연령대(4/5/6세)뿐"). 존재하면 실패하는 계약 테스트(M7)로 고정한다.

응답 200: `SessionScript` — 스키마는 `contracts/session-script.schema.json`이 정본.

**핵심 계약: 이 엔드포인트는 실패하지 않는다.**
백엔드가 키 부재로 500을 내든, 빈 배열을 주든, 미지 카테고리로 헛돌든, BFF는 **저작 폴백 데크로 SessionScript를 완성해 200을 반환**한다. `source.fallback_reason`에만 사유가 남는다.
→ **아이 화면은 백엔드 실패를 인지할 수 없어야 한다.** 이것이 1단계 합격선이다.

### 2.4 오류 봉투 — BFF가 실패를 반환하는 유일한 형태

`/api/session`은 위 계약상 실패하지 않으므로, 이 봉투는 `/api/health`와 `/__dev` 경로에만 나타난다.
```json
{ "ok": false, "code": "INVALID_CATEGORY", "message_for_dev": "…", "correlation_id": "a1b2c3d4" }
```
- `code`는 기계용 enum. `message_for_dev`는 **개발자 전용**.
- 🚨 이 문자열은 아이 화면에 도달하지 않는다. `uiux기획/CLAUDE.md:81` — "빨강은 오류 표시에 쓰지 않는다. **아이 화면에 오류 색 자체가 없다.**" 오류가 없는 게 아니라 오류 *표현*이 없다.
- SDK 예외 원문은 서버 로그에만 남긴다(`main.py:74-75`가 클라이언트로 흘리는 것을 BFF가 차단).

## 3. 주입 규칙 — 백엔드 값이 SessionScript로 가는 정확한 경로

**이 표가 정본이다.** 여기에 없는 조합은 주입하지 않는다.

| 백엔드 `Scenario` 필드 | 목적지 | 변형 |
|---|---|---|
| `ai_first_message` | `turns[0].ask.t` | **없음. 문자 단위 그대로.** 어댑터가 손대지 않았음을 T8이 검증한다 |
| `background` | `lines.intro.t`의 상황 설명 부분 | 저작 문장에 삽입 |
| `scenario_title` | `parent_meta.scenario_title` | 없음 |
| `learning_goal` | `parent_meta.learning_goal` | 없음. **아이 화면 비노출** |
| `conflict_trigger` | `parent_meta.conflict_trigger` | 없음. **아이 화면 비노출** |
| `category` | `other`(상대역 캐릭터) 선택 키 + `category` 반영 | 매핑 |
| `issues[]` | `parent_meta.dev_issues` | 🚨 **개발자 전용. 보호자 노출 금지** (§1.3-3 근거) |

**저작 데크에서 오는 것(백엔드 무관):** `lines.ai_disclosure`, `lines.demo_in`, `lines.demo[3]`, `lines.wait`, `lines.cant`, `lines.cheer`, `lines.party`, 그리고 `turns[*]`의 `hint`/`sup1`/`sup2`/`back`/`emo`/`back_emo` 및 `turns[1..2].ask`.

**총계: 아이가 듣는 발화 중 백엔드 유래는 정확히 1줄(`turns[0].ask`)이고 저작물이 나머지다.**
그 1줄이 실제 LLM 문장으로 아이 화면 말풍선과 TTS에 나오는 것이 수직 슬라이스의 증명 대상이다. 1단계 신규 저작 비용은 0줄이다 — `ownership_turn` 15줄이 `mockup-v1.html:916-935`에 이미 있다.

## 4. 프런트 소비 규칙

### 4.1 `lines.ts` 단일 소유 (규칙 9의 확장 해석)

`web/src/audio/lines.ts`가 다음 셋의 **유일한 소유자**다:
1. 정적 시스템 대사
2. 카테고리별 저작 폴백 데크
3. 서버 `SessionScript`를 최종 대사로 확정하는 `resolveSession()`

컴포넌트·스크린은 문자열 리터럴을 갖지 않는다. **서버가 준 문장도 반드시 `lines.ts`를 경유한다** — 이 경유가 없으면 S4 검사(서버 문자열의 무검증 TTS 도달 차단)가 우회된다.

### 4.2 🚨 `speak()` 관문

```
speak(x)  where x ∈ { LINES.* , sanitizeForChild(...) }   ← 이 둘만 허용
```

`speak(scenario.ai_first_message)` 같은 직접 전달은 **0건이어야 하며 S4가 기계적으로 강제한다.**

근거: `rule_engine/validator.py:11-15`의 20단어 부분문자열 블랙리스트가 유일한 출력 가드레일이고, 격리 실행으로 다음이 **전부 통과**함을 확인했다 — `죽고 싶을 만큼 힘들었어. 자해했어.`(자해 필터 없음) / `옷 벗어봐. 야한 사진 보여줄게.`(성적 필터 없음) / `우리 반 전체가 너랑 안 놀 거야. 아무도 말 걸지 마.`(단어를 안 써서 통과). 반대로 `장애물 달리기를 했어요`는 `장애` 부분일치로 차단된다.
현행 데모는 화면 텍스트라 성인이 눈으로 걸러내지만, **통합 후에는 글자를 못 읽는 만 4~6세의 귀로 직접 들어가고 걸러낼 사람이 없다.**

### 4.3 감정 바인딩 금지 (S1 — 최상위 불변식)

`back_emo`는 아이 발화의 **채점이 아니라 상황 전개의 결과**다. 파트너(송편)의 감정은 아이 발화에 절대 바인딩되지 않는다.

> `mockup-v1.html:1609-1613` — "⚠⚠ 절대 규칙: 송편은 상황에 반응한다. **아이의 발화에는 반응하지 않는다.** … 아이는 예외 없이 그것을 '내 대답에 대한 채점'으로 읽는다"
> `:1799` — "감정은 joy 가 아니라 surprised — **채점이 아니라 목격이다**"

3턴 감정 궤적은 누그러지는 방향만 허용된다: `angry/surprised → sad/none → shy/joy`.

### 4.4 재시도는 턴을 소비하지 않는다 (S2)

`retry_max=2`. 지원 escalation: `hint → sup1 → sup2(함께 말하기) → 턴 완결`. 벌이 아니라 지원 수준 상향이다(`캐릭터연출_기획_v1.md:653-663` 확정).

### 4.5 지연 은닉 (M5)

`POST /api/session`은 Gemini 최대 2회 호출로 수 초가 걸리고 스트리밍이 없다. 프런트는 **인트로 내레이션 중에 prefetch**한다.
인트로+`demo_in`+`demo[3]` = TTS 5발화로 대략 10초 이상이므로 그 안에 끝나면 아이는 대기를 인지하지 않는다. 초과 시 `thinking` + `lines.wait` 재생.
🚨 **로딩 스피너 금지** — `uiux기획/CLAUDE.md:128`이 캐릭터 `thinking` 상태로 대체하라고 명시.

## 5. 백엔드 부재 항목 (1단계 범위 밖 · 계약만 예약)

| 항목 | 상태 | 근거 |

### `backend_session` 어댑터 전환 선행조건 4건

`source.adapter`를 `backend_session`으로 켜기 전에 **반드시** 완료해야 한다. 하나라도 빠지면 아동 안전 회귀다.

1. `validator.py:29-30` `_flatten_text` 재귀화 — 현재 top-level `str`만 스캔한다. 중첩 턴 트리를 추가하면 아이가 듣는 15줄 전부에 금칙어 스캔이 **돌지 않는다**(실측: 중첩 `{'x':'칼로 협박했다'}` → `is_valid=True`)
2. `validator.py` `_REQUIRED_OUTPUT_FIELDS` 턴 트리까지 확장 — 현재 6개 고정 리스트라 신규 필드는 무검증
3. 규칙 6(오답 페널티 금지) 위반 검사 신설 — `validator.py`에 항목 자체가 없어 LLM이 어겨도 통제 수단이 없다
4. `validator.py:71-73` fail-open 정책 재결정 — `GDL-002` 카테고리 위반(`severity="high"`)이 통과한다(실측: 잘못된 category + HTML 페이로드 → `is_valid=True`)

## 6. 미확정 (T8 이전 해소 필요)

1. **LLM 스냅샷 3종 미채취** — 환경에 `GEMINI_API_KEY`가 없다. `generate.ownership_turn.200` / `generate.empty.200` / `generate.502` 보류. 채취 명령은 `contracts/backend-observed/README.md`. 키 없이는 LLM 관통 증명이 픽스처 재생으로 격하되며, 그 사실을 T8 결과에 명시해야 한다.
2. **`skill` ↔ `category` 매핑 불완전** — UI 5스킬 중 `refuse`↔`ownership_turn`, `take_turns`↔`rule_violation`만 성립. `greet`/`request`/`apologize`는 백엔드 카테고리에 대응물이 없다(백엔드 4종은 전부 *갈등* 카테고리다). `docs/02` 참조.

4. **말풍선 화자 구분** — `작업기록_UIUX_v1.md:555-556`의 알려진 미결. "글자 끄기" 상태에서 화자 단서가 입 움직임뿐이다. 1단계에서는 미결로 기록하고 판정 실패로 취급하지 않는다.
