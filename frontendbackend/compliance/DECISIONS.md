## D1 — 연령 타깃: 만 4~6세

**결정**: 1순위 대상 미취학 만 4~6세, 설계 기준 페르소나 만 5세. 상한을 두지 않으며 초1~3은 확장 경로.

**근거**: 이것은 **충돌이 아니었다.** 세 산출물이 갈라져 보였지만
- `아이디어_개발_기획서_양식반영본_v4.md:119` (최신 기획) — "1순위 대상은 미취학 만 4~6세, 설계 기준 페르소나는 만 5세… 상한은 두지 않습니다… 초1~3 확장의 경로"
- `프론트/CLAUDE.md:3` — 만 4~6세. `:129`가 통합을 **명문 금지**("만 7세 이상은 이 앱의 톤을 '애기 같다'고 거부한다")
- 백엔드 `prompts/prompt_config.json:2` — 초등 저학년(7~9세)

백엔드의 `age_range`는 enum 없는 `Optional[str]` **런타임 인자**(`webapp/main.py:43`)다. 즉 **백엔드가 이미 호출자에게 결정을 위임**했으므로 "백엔드 절대 기준" 규칙의 판정 대상이 아니다. 남은 것은 산문 1줄이며 벤더링 사본으로 처리했다.

**검토한 대안**: (B) 7~9세로 통일 → 목업 2,369행·에셋 22개·연출 가이드 전면 재작업. 해커톤 기간 내 불가. (C) 두 프로필 병행 → 톤 세트 2개 + 난이도 계단 2개. Phase 2.

**파급 파일**

- ✅ `knowledge_base/guideline/GDL-001_아동발달_사회정서_지침.md` — **2026-08-05 만 4~6세 기준 전면 재작성 완료**

## D2 — 1단계 범위: STT 제외

**결정**: 분석 문서 + 수직 슬라이스. 마이크는 렌더하되 비활성. TTS는 온디바이스 Web Speech ko-KR로 포함.

**안전 근거**: STT를 제외하면 **아동 음성이 기기를 떠나지 않는다.** `LEGAL-003-R1`(법정대리인 동의), `GOV-002-R2`(STT 벤더 위탁 계약), `GOV-001:21`(국외이전 조항)이 1단계에서 전부 미발동한다. 백엔드가 무상태(DB·세션·인증·로깅 0)여서 **동의 사실을 기록할 곳조차 없다**는 사실과 정합한다.

**대가**: LLM 관통은 증명되지만 "아이가 말하고 앱이 듣는" 핵심 경험은 아직 없다.

**파급**: `web/src/components/MicButton.tsx` (`disabled` 기본 true), `web/src/lib/classifyChildUtterance.ts` (작성됐으나 미호출), `RISK-ESCALATION-POLICY.md`

## D3 — 프런트 스택: Next.js 15 웹

**결정**: `프론트/CLAUDE.md:19`의 사전 승인 조항 발동 — "웹으로 갈 거면 이 블록만 Next.js 15 App Router + CSS Modules 로 교체."

**결정적 근거 (실물로 확인됨)**: 캐릭터 감정 표현이 **SVG 내부 CSS `display` 토글**로 설계되어 있다(`songpyeon-green.svg`의 `.m-smile`/`.m-frown`/`.blush`/`.tear` …). `<img>`로 넣으면 외부 CSS가 내부에 닿지 못해 표정이 전혀 바뀌지 않는다. RN에서 재현하려면 감정 8종 × 캐릭터 11종을 `react-native-svg`로 전부 재작성해야 한다.

부수 근거: TTS(Web Speech ko-KR)·효과음(Web Audio 오실레이터 8종, 사운드 파일 0개)이 목업에서 이미 동작 / BFF가 Next 산출물을 서브해 **CORS 항목 소멸** / `작업기록_UIUX_v1.md:548-549`가 이식을 승인.

**기각**: iframe 래핑 — `LINES`가 스크립트 내부 `var`(`mockup-v1.html:900`)라 서버 데이터 주입이 `postMessage` 주사가 되어 연동이 아니라 위장이 된다. `check:ui` 게이트가 iframe 내부를 볼 수 없다. 시연 바가 아이 화면에 남아 규칙 8 위반.

## D4 — 원본 무수정 · engine/ 사본에서 작업 (2026-08-05 개정)

**최종 결정**: 원본 두 폴더를 **한 바이트도 수정하지 않는다.** 규칙 엔진은
`engine/`(원본 `Communication_simulator` 사본, 포크 기준 `bdd1bc7`)에서 작업한다.

**경위**: 당초에는 원본을 직접 수정하되 사본·기록을 남기는 예외 절차였다(2026-08-04, 4건 실행).
2026-08-05 사용자 결정으로 전환했고, 원본에 가했던 4건을 `git checkout -- .` 으로 전부 되돌렸다.

**이 전환이 푼 것**: "상류 PR 권한 확인 필요"로 막혀 있던 **CS-002(fail-open)·CS-006(중첩 스캔)을
직접 고칠 수 있게 됐다.** 둘 다 HIGH 이고 G1 이었으며, 유일한 차단 사유가 소유권이었다.

**이 전환이 없앤 것 3가지**
| 제거된 우회 | 대체 |
|---|---|
| `prompt_config` 벤더링 + 모듈 속성 오버라이드 | `engine/prompts/prompt_config.json` 직접 수정 |
| `get_applicable_rules` top_k in-process 래핑 | `engine/rule_engine/rule_engine.py` 직접 수정 |
| 원본 트리 경로 탐색(한글·공백 취약) | 프로젝트 내부 상대 경로 |

**유지되는 것**: HTTP 계층(CORS·enum 검증·오류 정규화·타임아웃·헬스체크)은 계속 BFF 담당이다.
그리고 **API 계약(카테고리 4키·라벨)은 engine/ 이 우리 것이 되어도 백엔드 절대 기준**을 유지한다.

**회귀 방지**: `test_upstream_repo_is_untouched`(원본 git clean) +
`test_backend_contract_keys_match_upstream`(계약 키 바이트 동일).
포크 기록: `compliance/engine-fork/FORK-LOG.md`

**유지 조건 (G2-A — 리포트 구현 시 게이트)**
