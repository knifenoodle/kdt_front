## 0. 왜 떡인가 (설계 근거)

만 4~6세는 글자를 못 읽는다(`CLAUDE.md` 규칙 4). 그래서 캐릭터는 **형태만으로 구분되어야**
한다. 떡은 이 조건을 그냥 만족한다 — 반달(송편) / 층층(시루떡) / 길쭉(가래떡) / 네모(인절미) /
작은 원(꿀떡) / 꽃(약과) / 김 나는 네모(백설기). 색을 지우고 실루엣만 남겨도 누가 누군지 안다.

## 1. 2계층 구조 (스킬:캐릭터 1:1 매핑 아님)

```
파트너   송편        — 항상 곁에 있다. 진행·공감·칭찬. 모든 세션에 등장
상대역   나머지 전원  — 상황마다 교체 등장. 아이가 연습할 대상
오브젝트 무지개떡     — 캐릭터 아님. 진행도·보상 표시
```

**스킬마다 캐릭터를 새로 만들지 않는다.** 스킬이 늘면 상대역만 갈아 끼운다. 아이 입장에서
"내 편은 항상 같은 애"라는 안정감이 생기고, 캐릭터 무한증식도 막는다.

| 연습 | 상대역 | 목업 상태 |
|---|---|---|
| 싫다고 말하기 (거절·경계) | **시루떡** | ✅ 구현 |
| 인사 | 가래떡 | 예고만 |
| 부탁·도움 요청 | 꿀떡 | 예고만 |
| 사과 | 약과 | 예고만 |
| 차례 지키기 | 인절미 | 예고만 |
| 진정하기 | 백설기 | 예고만 |

## 2. 캐릭터별 사양

### 송편 — 파트너
- **형태**: 반달(아래가 평평한 돔). 위에 오므린 주름선 1개
- **몸통색**: 아이가 3개 중 고른다 (실제 송편이 쑥·흰·분홍인 것을 그대로 씀)

| 키 | 이름 | 몸통 | 그림자 |
|---|---|---|---|
| `green` | 쑥 (기본) | `#A8CE86` | `#8FBB6C` |
| `white` | 흰 | `#F7F2E7` | `#E2D9C6` |
| `pink` | 분홍 | `#F4B6C6` | `#E29AAE` |

- **포인트**: 깨소금 노랑 `#FFC12E` 3점 (몸통색과 무관하게 고정)
- **cantHear 전용 파츠**: 왼쪽에 손(타원 2겹). 이때만 표시
- 색 선택 UI는 시작 화면. 88×88 스와치 3개, 단일 탭, **글자 없음**.
  CSS 변수(`--song-body`)만 바꾸므로 모든 화면의 송편이 동시에 바뀐다

> ⚠️ **분홍은 `CLAUDE.md` 3절의 예외다.** 사용자가 이 건에 한해 명시적으로 허용했다.
> 원 규칙이 막으려던 것은 *서비스가 성별로 색을 배정하는 것*이고, 여기서는 **아이가
> 직접 고른다**. 단 **기본값은 반드시 쑥색**이며, 분홍을 기본값으로 올리거나 캐릭터
> 성별을 암시하는 데 쓰면 원래 문제가 그대로 돌아온다. 이 예외는 **송편 몸통색에만**
> 적용되고 다른 캐릭터·UI 요소로 확대하지 않는다. 상세는 `작업기록_UIUX_v1.md` §7.

### 시루떡 — 갈등 상황 상대역
- **형태**: 켜켜이 층. 위에서부터 켜(두꺼움·얼굴 있음) / 팥 / 켜 / 팥 / 켜
- **색**: 켜 `#F0E2C6`, 팥 `#8E4A6B`
- **톤**: 무서운 악당이 아니다. **소통 방식이 서툴러서 툴툴대는 캐릭터**다
- 🚫 **아이를 탓하는 대사 금지** (`CLAUDE.md` 규칙 6). 툴툴대는 대상은 늘 *상황*이다
- **마음 열림 연출**: 아이가 제대로 표현하면 `openHeart()` — **① 0.2초 정지 →
  ② 몸이 한 번 크게 부풂 + 개방음(392→523→659Hz) → ③ 층이 벌어지고(`.opened`)
  팥고물 6알이 톡 흩어진다(`.bursting`)**. **즉각·과장되게.** 만 4~6세는 마음이론이
  형성되는 시기라 "내 말이 상대를 바꿨다"가 이 앱의 가장 강한 학습 지점이다
  - ①의 정지가 핵심이다. **멈춘 뒤에 움직여야 "변했다"가 읽힌다**
  - ②는 **캐릭터 무관한 공통 신호**다. 상대역이 시루떡이 아니어도 재생된다.
    ③의 층 벌어짐만 시루떡 고유 연출로 그 위에 얹힌다
  - 🚫 **꿀폭죽과 섞지 않는다.** 폭죽은 *화면 전체·20알·섬광 있음*,
    여기는 *캐릭터 국소·6알·섬광 없음*. 섞으면 두 연출이 같아진다
  - 🚫 **이 순간 송편을 기뻐하게 만들지 않는다.** 아이 발화 직후라 "내 대답이 정답"으로
    읽힌다(규칙 6의 정답 공개가 표정으로 우회된다). 송편이 **아이가 아니라 시루떡 쪽을
    보고** 놀랄 수 있는 시선 채널이 생긴 뒤에 넣는다

### 가래떡 — 인사
- 길쭉한 둥근 기둥 `#F8F2E6` + 조청 모자 `#FF8A47`(= `character` 토큰)
- 말할 때 몸이 세로로 살짝 늘어난다(squash & stretch)

### 인절미 — 차례 지키기
- 모서리가 아주 둥근 정사각 `#F3EBD8` + 콩고물 점 `#D9B872` 4개

### 꿀떡 — 부탁·도움 요청
- 캐릭터 중 **가장 작게 그린다**. 원 `#F6F0E4` + 속 꿀 `#E8A93C` 55% 비침
- 작아서 아이보다 어린 존재로 읽힌다 → 아이가 도와주는 **역방향 연습**까지 한 캐릭터로 커버

### 약과 — 사과·화해
- 꽃 각인(원 8개 방사 + 중앙 원). 색 `#E3B472` / 중앙 `#EFC98F`
- 🚫 갈색으로 어둡게 칠하지 않는다(`CLAUDE.md` 3절 — 갈색은 면적색 금지). 조청 금빛까지만
- **화해 연출**: 갈라졌다가 조청으로 다시 붙는 애니메이션 (미구현, 사과 모듈에서)

### 백설기 — 진정·기다리기
- 흰 네모 `#FBF8F3` + 김 3줄. 김은 `--ink-soft` 40~50% 투명 (흰색이면 배경에 묻힌다)
- 김 오르내림을 그대로 **호흡 가이드 애니메이션**으로 쓴다

### 무지개떡 — 보상 오브젝트
- 6층, 아래가 넓은 사다리꼴 실루엣 + 바닥 그림자
- 채운 층 `opacity:1`, 안 채운 층 `opacity:.16`
- 연습 1회 = 1층. **숫자·점수·스탬프·스트릭을 쓰지 않는다** (`CLAUDE.md` 8절)

#### 완성 보상 — 여러 종류를 돌아가며 쓴다

6층을 다 채우는 순간에만 발동한다. **한 번에 다 보여주지 않는다.**
매번 같은 연출이면 세 번째부터 아무 의미가 없다. 완성할 때마다 다음 연출로 넘어간다.

```
1회차 → 🍯 꿀파티   2회차 → 🏊 꿀수영장   3회차 → 🫓 떡메치기   4회차 → 다시 꿀파티 …
```

세 연출은 **채우는 축이 서로 다르다.** 이게 순환의 근거다.

| 연출 | 성격 | 방향 | 주인공 |
|---|---|---|---|
| 🍯 꿀파티 | 떠들썩 | 위에서 쏟아짐 · 화면 전체 | 꿀 |
| 🏊 꿀수영장 | 잔잔 | 아래에 고임 · 화면 하단 | 꿀 |
| 🫓 떡메치기 | **리듬** | **중앙 무대** | **떡 자신 (캐릭터가 행위자)** |

**공통** (어떤 연출이든)
| 요소 | 연출 |
|---|---|
| 꿀 코팅 | 무지개떡 맨 위에 꿀이 얹히고 옆으로 흘러내린다 (0.9초, 위→아래 scaleY) |
| | 🚫 **층을 가리지 않는다.** 6층이 다 보여야 "다 모았다"가 읽힌다 |
| | ⚠ **떡메치기에는 얹지 않는다**(`noCoat`) — 꿀을 섞는 순간 성격 구분이 무너진다 |
| 황금빛 | 화면 중앙에서 퍼지는 은은한 금빛 (radial glow) |
| 생동감 | 송편은 빠르게 깡충, 축하 글자는 커졌다 작아지고, 무지개떡은 좌우로 흔들 |

| 요소 | 연출 |
|---|---|
| 꿀단지 | 팝 하고 나타나 −16° 기울어 붓고, 이후 주기적으로 더 기운다 |
| 꿀 줄기 | 단지 입구에서 168px만 떨어진다. 🚫 **길게 늘이지 않는다** — 화면이 세로로 갈린다 |
| 꿀폭죽 | 섬광 + 퍼지는 링 + 입자 20개. 처음 4발 연달아, 이후 2.6초마다 |
| | 🚫 **흰색·연한 크림 입자를 쓰지 않는다** — 밝은 배경에 묻힌다. 꿀비보다 진한 호박·주황 |
| 꿀비 | 꿀방울 26개가 무작위 크기·속도로 낙하 (폭죽이 묻히지 않게 성기게) |
| 소리 | 꿀 흐르는 하강음 4개 → 축하 아르페지오 5개 → 폭죽마다 짧은 톤 |

|---|---|
| 꿀 웅덩이 | 화면 하단이 꿀. 물결 2겹이 좌우로 흐른다 (7초 루프, 이음매 없이) |
| 물놀이 | 꿀떡·송편·인절미·시루떡이 꿀에 잠겨 통통 뜬다. 꿀떡(분홍)·인절미(파랑)는 튜브 |
| 소리 | 첨벙거리는 낮은 톤 5개 |
| | 🚫 **폭죽·꿀비를 섞지 않는다.** 잔잔한 것이 이 연출의 성격이고, 섞으면 A와 구분이 사라진다 |

**보상 C — 🫓 떡메치기** (`fx-pound`) · 리드미컬한 쪽
| 요소 | 연출 |
|---|---|
| 무대 | 화면 중앙에 절구. 무지개떡이 그 안에 얹힌다 (절구는 떡 뒤 레이어) |
| 치는 이 | **인절미** — 인절미는 실제로 떡메로 쳐서 만드는 떡이다. 배정에 근거가 있다 |
| 박자 | **0.9초 간격 × 4회.** 이 리듬이 다른 두 연출에 없는 축이다 |
| 타격 반응 | 칠 때마다 무지개떡이 눌렸다 부푼다 (scaleY .93 → 1.04) |
| 입자 | 칠 때마다 **콩고물 7알** (골드 `#D9B872`, 짧은 거리, **섬광 없음**) |
| 마무리 | 4타 뒤 무지개떡 맨 위에 **광택**이 뜬다. 꿀 코팅과 다른 표현이라야 성격이 안 겹친다 |
| 소리 | 196Hz 짧은 타격 4번 → 마지막에 밝은 3화음 |
| | 🚫 **꿀비·꿀폭죽·꿀 웅덩이·꿀 코팅을 일절 섞지 않는다** |
| | ⚠ 절구를 **어두운 나무색으로 칠하지 않는다**(갈색 면적색 금지). 밝은 베이지 `#E8DCC4` / |
| | 그림자 `#D3C3A4`, 화면 면적 4% 미만. 금지 조항의 취지는 어둡고 탁한 색이 화면을 덮는 것이다 |
| reduced-motion | 타격·입자 없음. 대신 **광택이 4단계로 계단식** 상승 + 소리는 그대로 4박 |

> 🚫 **기각한 후보와 근거** — *나눠먹기*: 무지개떡이 사라진다. 6세션에 걸쳐 쌓은
> **성취의 증거**를 없애는 연출은 보상이 아니라 회수로 읽힌다. *단체사진*: 정적이라
> 보상감이 약하고 '사진 찍기'라는 사회적 개념 자체가 이 연령대엔 아직 얕다.

**보상이 끝나도 세션은 끝난다** (`CLAUDE.md` 규칙 7). 보상은 오버레이일 뿐이고
`끝` 버튼은 계속 눌린다(`pointer-events:none`). 무한 루프로 붙잡지 않는다.

**끝을 누르면 무지개떡은 0층으로 리셋되고 새 판이 시작된다.** 다 모은 상태로 남겨두면
다음 세션마다 보상이 반복되어 의미가 닳는다.

`prefers-reduced-motion` 이면 두 연출의 모든 움직임이 정지한다(전역 규칙).

**앞으로 늘릴 자리:** `REWARDS` 배열에 `{k, nm, cheer, line, run}` 한 줄을 더하면
자동으로 순환에 낀다. 새 연출은 **위 세 축과 겹치지 않는 축**을 채워야 한다 —
겹치면 순환의 의미가 없다.

## 4. 5개 상태 표현 (`CLAUDE.md` 4절)

모든 캐릭터가 같은 방식으로 상태를 표현한다. SVG에 `data-state` 를 주면 CSS가 처리한다.

| 상태 | 표현 |
|---|---|
| `idle` | 몸통 호흡(3.4s scale 1↔1.035) + 눈 깜빡임(5.2s) + 웃는 입 |
| `listening` | 몸 −5° 기울임 + 눈 1.25배 + 웃는 입. 마이크 버튼에 확산 링 2개 |
| `thinking` | 몸 +6° 갸웃 + 머리 위 점 세 개(엇갈린 딜레이) + 무표정 입. **스피너 금지** |
| `speaking` | 입이 열렸다 닫힘(0.26s alternate). 말하는 캐릭터에만 적용 |
| `cantHear` | 송편이 −8° 기울고 손을 귀에. 무표정 입. **실패가 아니라 캐릭터의 부탁** |
| | ⚠ **마이크 맥동과 호흡을 반드시 켜둔다.** 아이가 다시 말해야 하는 순간이다 — |
| | 여기서 신호를 끄면 화면이 죽는다. 호흡 3.0s(idle 3.4s보다 살짝 빠르게: 안달, 재촉 아님) |

`prefers-reduced-motion` 이면 모든 애니메이션이 꺼진다.

## 5. 감정 레이어 (7종)

**기능 상태와 감정은 서로 다른 축이다.** 말하면서 슬플 수 있어야 하므로 겹쳐서 표현한다.
SVG에 `data-state`(기능)와 `data-emo`(감정)를 각각 준다.

```
data-state="speaking" data-emo="sad"   →  입은 말하느라 움직이고, 눈썹·눈물은 슬픔
```

### 눈썹은 화남에만 쓴다
떡에는 눈썹이 없는 게 자연스럽고, 눈썹이 있으면 사람 얼굴처럼 보여 떡의 인상이 흐려진다.
나머지 감정은 **눈·입·부속만으로** 충분히 읽힌다. 다만 **화남만은 눈썹 없이 성립하지 않아서**
유일한 예외로 남긴다.

| 감정 | 눈썹 | 눈 | 입 | 부속 |
|---|---|---|---|---|
| `none` 무표정 | — | 보통 | 상태가 정함 | — |
| `joy` 기쁨 | — | 웃는 호 ( ^ ^ ) | 활짝 벌린 웃음 | 볼 홍조 + 반짝 3개 |
| `sad` 슬픔 | — | 살짝 큼 | 아래로 굽음 | 눈물 (2.6초 주기로 흐름) |
| `angry` 화남 | **안쪽 끝 내림 (유일)** | 가늘게(0.72) | 지그재그 | 볼 온기(주황 32%) |
| `scared` 무서움 | — | **가로 1.32 / 세로 0.74**, 아래서 눌림 | 오므린 작은 O | 땀방울 + **지속 떨림** |
| `surprised` 놀람 | — | **가로·세로 1.45**, 온전히 큼 | **크게 벌린 O** | 몸통 한 번 튐 |
| `shy` 부끄러움 | — | 웃는 호 | 작은 미소 | 볼 홍조 진하게(90%) |
| `proud` 뿌듯함 | — | 웃는 호 | 활짝 웃음 | 볼 홍조 + 반짝 |

### 무서움 ↔ 놀람 — 6채널로 갈라 놓았다

예전에는 둘 다 `눈 1.35 / O 입`이라 **차이가 땀방울 하나뿐**이었다. 지금은 이렇게 다르다.

| 채널 | 무서움 | 놀람 | 정적? |
|---|---|---|---|
| 눈 가로 | 1.32 | 1.45 | ✓ |
| 눈 세로 | **0.74 (눌림)** | 1.45 | ✓ |
| 눈 형태 | 아래에서 눌려 올라옴 | 온전한 원 | ✓ |
| 입 | 오므린 작은 O | 크게 벌린 타원 | ✓ |
| 부속 | 땀방울 | 없음 | ✓ |
| 몸 | **작게 계속 떤다** (0.13초) | **한 번 크게 튄다** (0.5초) | ✗ |

**5개가 정적**이라 `prefers-reduced-motion` 에서도 구분된다. 몸의 두 반응은 성격이
정반대다 — 지속 vs 1회. 이게 두 감정의 본질 차이이기도 하다.

> **눈꺼풀을 별도 도형으로 얹지 않았다.** 눈꺼풀은 몸통색이어야 자연스러운데,
> 그러면 8개 SVG 전부에 몸통색을 물려야 해서 결합도가 커진다. 대신
> `transform-origin` 을 위로 옮기고 세로를 눌러 **같은 도형으로** 같은 인상을 만든다.

### 눈은 4채널 변수로 쪼개져 있다

감정(크기)과 시선(방향)은 서로 다른 축인데 CSS `transform` 선언 하나로는 겹쳐 쓸 수 없다.
그래서 `--eye-sx / --eye-sy / --eye-tx / --eye-ty` 로 나눠 독립적으로 얹는다.

| 축 | 쓰는 곳 |
|---|---|
| `--eye-sx` `--eye-sy` | 기능 상태(listening 1.25)와 감정(위 표) |
| `--eye-tx` | **시선** — `data-gaze="in"` 이면 상대를 본다 |

**시선은 "누구에게 하는 말인가"를 눈으로 가리키는 채널이다.** 두 곳에서 쓴다.
① 시범 모드 — 둘이 서로를 본다(= 둘 사이의 일) / ② 마음 열림 — 송편이 아이가 아니라
상대역을 본다(= 채점이 아니라 목격).

### 감정 전이 — 눈 감았다 뜨는 사이에 바꾼다

입·부속은 `display` 스왑이라 크로스페이드가 **물리적으로 불가능**하다. 그래서 페이드 대신
부위가 바뀌는 프레임을 **눈꺼풀 뒤에 숨긴다.** 사람도 표정을 바꿀 때 눈을 깜빡인다.

```
setEmo() → .emo-blink (눈 감김 110ms) → 감긴 사이에 data-emo 교체 → 뜨기  ·  총 260ms
```

- **큐잉하지 않는다.** 만 4~6세는 원인과 결과를 짧은 시간창 안에서만 잇는다. 대사보다
  표정이 늦게 오면 인과가 끊긴다. 새 감정이 들어오면 즉시 교체(마지막 것만 적용).
- ⚠ **비교 대상은 현재 속성이 아니라 예약된 목표다.** 현재 속성으로 비교하면
  "sad 예약 → 곧바로 none 요청"에서 none 이 '이미 none'으로 착각해 조기 반환하고,
  취소됐어야 할 sad 예약이 뒤늦게 실행된다. 실제로 이 버그로 시범 직후 송편이 슬픈
  얼굴로 굳었다.
- `prefers-reduced-motion` 에서는 깜빡임 없이 즉시 교체 = 예전과 동일한 동작.

### 파트너 송편의 감정 동조

상대역이 화를 내는데 송편이 같은 얼굴이면 **아이 옆에 아무도 없는 것과 같다.**
단, 한 단계 약하게(`data-emo-soft="1"` — 부속만 끄고 눈·입은 남긴다).

| 상대역 | 송편 | 왜 |
|---|---|---|
| angry | **none** | 같이 화내면 아이가 둘 사이에 낀다. 중립이라야 "내 편"이 유지된다 |
| scared | **none** | 같이 무서워하면 아이의 불안이 증폭된다 |
| sad | sad(약) | 공감 |
| shy | joy(약) | 격려 |
| surprised | surprised(약) | 함께 놀란다 |
| joy · proud | joy(약) | 함께 기뻐한다 |

> ⚠️⚠️ **송편은 상황에 반응한다. 아이의 발화에는 반응하지 않는다.**
> 동조는 `askTurn`(상대역이 감정을 드러내는 순간) **한 곳에서만** 일어나고,
> `respond`(아이 발화 직후)에서는 송편의 감정을 **절대** 바꾸지 않는다.
> respond 구간에서 표정이 바뀌면 시간적 근접성 때문에 아이는 예외 없이 그것을
> **"내 대답에 대한 채점"** 으로 읽는다 — 규칙 6이 금지한 정답 공개의 우회다.
> 유일한 예외가 마음 열림인데, 거기서도 감정을 joy 가 아닌 surprised 로 두고
> **시선을 상대역 쪽으로 돌려** 반응의 대상이 아이가 아님을 눈으로 못박는다.

### 🚫 화남에 뿔·김·화 표시를 쓰지 않는다
초안에서 화남에 김(스팀) 두 줄을 머리 위에 얹었더니 **도깨비 뿔로 읽혔다.**
시루떡은 악당이 아니므로(2절) 부속을 빼고 **눈썹·입·볼 온기만으로** 표현한다.
같은 이유로 만화식 분노 마크(십자 혈관), 붉은 얼굴, 찡그린 이빨을 쓰지 않는다.

### 감정은 아이를 향하지 않는다
`CLAUDE.md` 규칙 6과 직결된다. 시루떡이 화나거나 슬픈 대상은 **언제나 상황**이며,
아이의 대답이 틀려서가 아니다. 아이의 발화 뒤에 오는 감정은 반드시 **누그러지는 방향**
(화남 → 놀람 → 무덤덤 → 기쁨)으로만 전개한다. 반대 방향으로 악화시키지 않는다.

### 목업 시나리오의 감정 전개
```
1턴  시루떡 angry(요구)      → 아이 말 후  surprised(어? 안 된다고?)
2턴  시루떡 sad(아쉬움)      → 아이 말 후  none(받아들임)
3턴  시루떡 shy(조심스럽게)  → 아이 말 후  joy + 층 펼쳐짐
보상 송편 proud
```

## 6. 배경 장소 (10곳)

연습이 벌어지는 장소를 실제 공간처럼 보이게 그린다. 만 4~6세는 맥락이 구체적일수록
전이(generalization)가 잘 되므로, 추상적인 무대가 아니라 **아이가 실제로 가는 곳**을 쓴다.

| 키 | 장소 | 알아보게 하는 요소 |
|---|---|---|
| `class` | **교실 (유치원)** ★ | 옅은 민트 화이트보드, 사물함, 게시판 그림, 책상 3개 |
| `play` | **놀이터** ★ | 그네, 미끄럼틀, 모래밭, 나무, 굴러다니는 공 |
| `kids` | 키즈카페 (기본) | 무지개 벽화, 삼각 가랜드, 볼풀, 미끄럼틀, 풍선 |
| `cvs` | 편의점 | 유리 냉장 진열장 3칸, 곤돌라 진열대, 계산대·POS, 천장 형광등 |
| `stat` | 무인문방구 | 벽면 문구 진열대, **셀프 결제 키오스크**, 안내 배너, 포스터 |
| `variety` | 생활용품점 | 좁은 통로, 빼곡한 5단 진열대, **노란 가격표** |
| `dept` | 백화점 | 대각선 에스컬레이터, 유리 난간, 매장 간판·쇼윈도·마네킹, 화분 |
| `cinema` | 영화관 | 밝은 스크린, 곡선 좌석 2열, 바닥 유도등 |
| `futsal` | 풋살장 | 인조잔디 스트라이프, 골대·골망, 철망 펜스, 조명탑 |
| `dojang` | 태권도장 | 벽거울, 색깔 띠 걸이, 격파판, 현수막, 체크 매트 |

> ★ **교실·놀이터는 5단계(실사)와 겹치라고 일부러 넣은 곳이다.**
> 예선 기획서 4슬라이드가 5단계 실사 배경으로 이 둘을 지목했는데, 1~4단계에서
> 한 번도 가보지 않은 장소가 5단계에서 처음 나오면 **"연습한 맥락 → 실전 맥락" 전이가
> 성립하지 않는다.** 같은 장소를 SVG → 실사로 넘기는 것이 전이 설계의 핵심이다.
> (판단 근거: `캐릭터연출_기획_v1.md` §2-D)

### 구현 원칙
- **전부 인라인 SVG. 외부 이미지 0개** — 사진·CDN·폰트를 쓰지 않는다는 원칙 유지
- 배경에 `filter:saturate(.8)` + 위아래 스크림을 깔아 **캐릭터가 항상 앞에 오게** 한다.
  배경이 시선을 뺏으면 그 순간 이 앱은 실패한다 (`CLAUDE.md` 3절)
- 영화관도 **검정을 면적색으로 쓰지 않는다.** 어두운 극장은 짙은 남보라(`#6B6894`)로 대신한다
- 태권도장 매트의 붉은색은 `opacity .55`로 낮춘다. 오류색이 아니라 바닥 재질이지만,
  아이 화면에서 붉은 면이 강하면 안 된다
- 장소 이름에 **실제 브랜드명을 쓰지 않는다.** 요청받은 '다이소'는 `생활용품점`으로 적는다 —
  목업이라도 실존 브랜드를 사칭하는 화면은 만들지 않는다

- 교실 칠판을 **검정·짙은 초록으로 칠하지 않는다.** 옅은 민트 화이트보드로 대신한다
- 10곳이 되면서 확인용 그리드를 2열 → **3열**로 바꿨다. 스크롤을 만들지 않기 위해서다

### 확인 방법
시연 바 **「장소 보기」** 또는 `#scenes`. 카드를 누르면 그 장소에서 연습이 바로 시작된다.
특정 장소로 바로 진입: `#scene-class`, `#scene-play`, `#scene-futsal` 처럼 키를 붙인다.

## 7. 캐릭터별 특기 동작 (전부 구현됨)

캐릭터 확인용 화면(`#cast`)에서 **「눌러보기」 배지가 붙은 카드를 탭**하면 재생된다.

| 캐릭터 | 동작 | 구현 |
|---|---|---|
| **약과** | 사과·화해 — 좌우로 갈라졌다가 **조청이 이어지며** 다시 붙는다 (2.6초) | `.mending` |
| | 꽃잎을 좌/우/중앙 3그룹으로 나눠 뒀다. 얼굴은 가운데에 남아 갈라지지 않는다 | |
| **가래떡** | 말할 때 몸이 세로로 늘어난다 (squash & stretch, 0.46초 왕복) | `[data-state=speaking] .gara` |
| **꿀떡** | 누르면 속 꿀이 2.1배로 차오르고 **한 방울이 흘러넘친다** | `.squeeze` |
| **시루떡** | 마음 열림 — 정지 → 부풂 → 층이 벌어지고 팥고물 6알이 튄다 | `.opened` `.bursting` |
| **전 캐릭터** | 마음 열림 공통 신호 — 정지 → 몸이 한 번 크게 부풂 + 개방음 | `.freeze` → `.heart-open` |
| **전 캐릭터** | 등·퇴장 — 아래에서 통통 튀며 등장, 아래로 작아지며 퇴장 | `.entering` / `.leaving` |

### 상대역은 갈아 끼운다 (화자 판정이 이름에 묶여 있지 않다)

`setOther('injeol')` 로 무대의 상대역을 교체한다. 화자 판정은 이름 목록 대조가 아니라
**배제**다 — **송편(파트너)이 아니면 전부 상대역**이다.

```js
function actorOf(speaker){
  return (speaker===PARTNER || speaker==='a-song') ? 'a-song' : 'a-other';
}
```

새 캐릭터를 추가해도 등록을 잊어서 입이 안 움직이는 일이 없다. 말풍선 이름도 같은
규칙을 타서 현재 상대역 이름으로 자동 교정된다. 확인: 시연 바 **「상대역 바꾸기」**
또는 `#other-injeol`.

> 이전 코드는 `speaker==='시루떡'` 문자열 비교였고, **상대역이 바뀌면 입이 영원히
> 안 움직였다.** 글자를 못 읽는 아이에게 "지금 누가 말하는가"의 유일한 단서가
> 입 움직임이라 연출 문제가 아니라 기능 결함이었다.

## 7-2. 시범(관람) 모드 — 아이 차례가 아닐 때

예선 기획서 2단계. 인트로 뒤에 송편↔시루떡의 모범 대화 3줄이 오간 다음 아이 차례가 온다.
설계의 전부는 **"지금은 내 차례가 아니다"를 오해 없이 아는 것**이다.

| 채널 | 시범(관람) | 실전 |
|---|---|---|
| **마이크 (주)** | `data-off="1"` — 잠들어 있음, 맥동 없음 | 깨어나며 맥동 |
| 턴바 (보조) | 감춤 — 시범은 턴이 아니다 | 표시 |
| 화면 톤 (보조) | `saturate(.5)` | `saturate(.8)` |
| 배치 (보조) | 둘이 서로를 향해 기욺 (7° / −6°) | 둘 다 정면 |

**주 신호를 마이크로 잡은 이유**: 이 나이대에 "내 차례인가"는 화면 톤이나 배치가 아니라
**누를 것이 살아 있는가**로만 판단된다. 톤·배치는 알아채는 데 학습이 필요하다.

- 🚫 **화면을 어둡게 하지 않는다.** 검정 면적색 금지(`CLAUDE.md` 3절).
  물러나게 하려면 **채도를 뺀다.**
- 시범은 `S.turn` 을 건드리지 않는다 → 3턴 규칙(규칙 7) 무영향
- 다시 듣기는 살려둔다. 마이크가 잠겨 있어 활성 버튼은 여전히 하나(규칙 8)
- 네 채널 중 **셋이 정적**이라 `prefers-reduced-motion` 에서도 구분된다.
  「글자 끄기」까지 켠 상태로 확인하는 것이 본 검증이다

진입: `#demo` 또는 시연 바 **「시범」**.

### 등·퇴장을 넣은 이유
즉시 나타나고 즉시 사라지면 만 4~6세는 **등장을 놓치거나 소멸에 놀란다.**
세션 시작에서 송편이 먼저, 180ms 뒤 상대역이 등장한다. 3턴이 끝나면 상대역이
퇴장한 뒤에 보상 화면으로 넘어간다 — 화면이 툭 바뀌지 않는다.

### 연타 대응
`.squeeze` · `.mending` 은 클래스를 뗐다가 **리플로우를 강제한 뒤** 다시 붙인다.
아이는 반드시 연타하고, 그때 애니메이션이 안 도는 것이 가장 흔한 실망 지점이다.

## 7-3. 오답 경로 — "긍정적인 재시도 루프"

예선 기획서 3슬라이드가 요구한 것을 `CLAUDE.md` 두 규칙과 동시에 만족시켜야 한다.

```
규칙 6 (페널티 없음)  → 재시도가 손실이 되면 안 된다  ⇒ 턴을 소비하지 않는다
규칙 7 (세션은 끝난다) → 무한 루프가 되면 안 된다      ⇒ 상한 2회
```

목업에 이미 선례가 있었다 — **`cantHear` 는 `S.turn` 을 올리지 않는다.** 그대로 따랐다.
`S.turn++` 은 교환이 완결되는 `respond()` 안에서만 일어난다.

상한에 닿으면 벌이 아니라 **지원 수준을 한 단계 올려** 턴을 완결시킨다.

| 시도 | 반응 | 턴 |
|---|---|---|
| 1차 실패 | 더 구체적인 힌트 — *"짧게 해도 돼. 「안 돼」 두 글자면 충분해."* | 그대로 |
| 2차 실패 | **송편이 함께 말해준다** — *"같이 말해보자. 하나, 둘… 「안 돼!」"* | 그대로 |
| 3차 | 지원과 함께 턴이 넘어간다 (아이를 붙잡아 두지 않는다) | +1 |

**3단계를 "선택지 제시"가 아니라 "함께 말하기"로 정한 이유**: 글자를 못 읽는 아이에게
선택지를 보이려면 두 발화를 **소리로만** 제시해야 하는데, 그러면 아이가 둘을 동시에
기억해야 한다. 이 나이대에는 한 문장을 따라 하는 쪽이 확실히 쉽다. 대신 따라 하기로
끝나지 않도록 **마지막 단계에서만, 핵심 어구만** 준다.

⚠ **상대역의 감정은 그대로 둔다.** 아이 발화 뒤에 상황을 악화시키지 않는다(§5).
재시도 중에도 시루떡은 더 화내지 않는다.

확인: 시연 바 **「틀린 답」** → 다음 발화가 오답으로 처리된다. 턴바가 안 움직이는 것을 본다.

## 9. 5단계(실사·또래 AI·결과 영상) 연계 원칙

5단계는 별도 트랙이라 여기서 구현하지 않는다. 다만 **캐릭터가 실사 맥락으로 넘어갈 때
아이가 같은 존재로 인식하려면** 아래가 유지돼야 한다.

1. **실루엣과 포인트색의 짝.** 형태(반달·층층·길쭉)와 고채도 포인트 1개.
   사실적으로 다시 그리는 순간 다른 캐릭터가 된다
2. **아이가 고른 송편 색.** 아이가 이 서비스에서 가진 **유일한 소유권**이다.
   여기서 초기화되면 "내 송편"이 아니게 된다
3. **배치의 문법.** 송편은 언제나 아이 편에서, 화면의 같은 쪽에, 상대역보다 작게
4. **감정 문법.** §5의 눈·입·부속 조합을 그대로 쓴다. 실사 톤에 맞춰 표정 체계를 새로
   만들면 아이는 학습한 표정 언어를 다시 배워야 한다
5. **부정 감정의 대상 규칙.** 5단계에서도 캐릭터의 부정 감정은 상황을 향한다

### 결정 — "갈등이 심화되는 상황" 영상

예선 기획서 5슬라이드는 결과 영상을 *"갈등이 해소되거나, **심화되는** 상황"* 두 갈래로 둔다.
**§5의 "아이 발화 뒤 감정은 누그러지는 방향으로만"과 정면으로 충돌한다.**
형식(점수·빨간 X)이 아니라 **기능(아이 발화 → 나빠짐)** 이 규칙 6의 금지와 일치한다.

> **판정: `CLAUDE.md`·이 가이드를 따른다.** 문서 위계가 명시돼 있고, 만 4~6세는
> 자연적 귀결과 처벌을 구분하지 못해 "네가 그렇게 말해서 나빠졌다"로 읽는다.
>
> **다만 덱을 폐기하지 않는다.** 덱 자신이 완충을 갖고 있다 — 5슬라이드의
> *"마스코트가 감정을 보듬고 대처 방법을 조언"*. 심화 장면을 **아이 발화의 귀결로
> 제시하지 않고**, 마스코트가 **먼저** 개입한 뒤 *"이렇게 될 수도 있었어"* 의
> **가정형**으로 보여주면 §5를 위반하지 않는다.
>
> 순서가 전부다 — 아이 발화 → 심화 영상 → 위로 (✗ 인과로 읽힌다)
> 　　　　　　　 아이 발화 → 마스코트 개입 → 가정형 예시 (✓ 설명으로 읽힌다)

### 결정 — "아동의 대답을 텍스트로 변환"

덱 4슬라이드의 이 문장은 표시 위치를 말하지 않는다. 셋으로 갈린다.

| 위치 | 판정 |
|---|---|
| 파이프라인 내부(STT 결과) | 충돌 없음. 규칙 4는 화면 규칙이다 |
| 보호자 리포트 | 충돌 없음. `CLAUDE.md` 5절이 "대화 리포트 전문"을 게이트 뒤로 이미 지정했다 |
| **아이 화면** | **충돌.** 글자를 못 읽는 아이에게 자기 발화를 글자로 보여주는 건 정보가 아니라 소음이다 |

> **판정: 파이프라인 내부 + 보호자 리포트. 아이 화면 노출 금지.**
> 새 판단이 필요 없다 — 규칙 4와 5절이 이미 이 배치를 지정하고 있다.
> 현재 목업의 아이 화면에는 아이 발화 텍스트가 **없다**(말풍선은 캐릭터 대사뿐).
